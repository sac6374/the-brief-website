# Read Market Brief — repo guide

Static Cloudflare Pages site for readmarketbrief.com. Full daily briefs live in
`briefs/YYYY-MM-DD.html` (generated by the 8 AM ET workflow run); short updates
in `updates/`; breaking alerts in `breaking/`. Generator: `scripts/generate_brief.py`
(prompt in `prompts/system_prompt.txt`). Routing/template checks: `scripts/validate_site.py`.
Never commit API keys; `ANTHROPIC_API_KEY` exists only as a GitHub Actions secret.

## EDITORIAL RULES — apply to every brief, every session

### Factual accuracy (highest priority)
- Never publish a financial term definition without verifying it. Curve
  terminology reference: bear steepener = long-end yields rise faster than
  short-end; bear flattener = short-end rises faster than long-end; bull
  steepener = short-end falls faster; bull flattener = long-end falls faster.
  The Term of the Day definition must match the market evidence cited in the
  same edition.
- If a claim in one section contradicts data in another, stop and reconcile
  before writing further.

### Number consistency
- Every statistic that appears more than once must use the identical value
  everywhere (no "+11%" in one section and "+12%+" in another).
- Before finalizing any edition, run a self-check: list every repeated
  statistic and confirm the values match across all sections.

### Redundancy limits
- A specific statistic may appear at most twice: once in the summary sections
  (s00/s01) and once in the section where it is actually analyzed.
- Each section must add a NEW angle. If a section only restates s01's numbers
  with connective tissue, rewrite or cut it.

### Analytical rigor
- Flag any EPS beat greater than 50% vs. consensus as likely containing
  one-time/non-operating items, and say so explicitly. Never call a 2-3x EPS
  beat an operational "blowout" without that caveat.
- Distinguish stock moves from sector moves. Never label a single stock's
  return as a sector return in Sector Lens — use the ticker or an actual
  sector/ETF figure.
- When citing percentage changes, always label the basis (MoM, QoQ, YoY) —
  never mix bases in adjacent sentences without labels.

### Pre-publish checklist (run before every edition ships)
1. Terminology verified against the reference above
2. Repeated stats reconciled
3. No stat appears more than twice
4. Outsized beats caveated
5. Sector labels are actually sectors
6. All % changes labeled with their basis
